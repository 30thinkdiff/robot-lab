# 怎样理解动作与实际运动面板

先分清三个对象：策略输出的是7维动作命令序列；OSC把本步命令变成末端位姿目标并计算关节力矩；MuJoCo在接触、惯性和约束下产生实际运动。当前SmolVLA没有直接给出一条未来真实状态轨迹。

## 时间基准

20Hz控制下，一个环境步为50ms。视频帧n对应提交动作u_n**之前**的实际状态；面板的“执行后”及本步误差对应执行完u_n的状态。末次执行后状态存在于motion记录中，但不在N帧视频中。播放速度改变的是本地回放速度，不改变当时的控制频率。GPU推理毫秒数属于墙钟时间，不能用来替代这50ms。

## 指标与单位

| 指标 | 计算/来源 | 可以说明什么 |
|---|---|---|
| 视频时刻位置 | MuJoCo末端site的世界坐标XYZ，m | 本步执行前的实际机械臂位置 |
| OSC真实目标 | 本步真实`set_goal`记录的目标位置/朝向 | 控制器本周期试图跟踪的位置，不保证这个目标有利于完成任务 |
| 本步执行后位置 | 执行u_n后读取的真实site坐标，m | 动力学和接触作用后的结果 |
| 本步OSC位置误差 | `norm(p_after−p_goal)`，界面显示mm | 一个50ms周期末的任务空间跟踪偏差；小误差不等于规划正确 |
| 本步OSC朝向误差 | `acos((trace(R_goal R_afterᵀ)−1)/2)`，数值裁剪后转为° | 目标与实际末端朝向的最短旋转角，不是关节角误差或Euler分量差 |
| 块名义端点 | 从动作块起点，按冻结输入缩放/裁剪规则逐个累积平移和旋转 | “每条增量都能理想跟踪”的解释；不是世界模型预测，忽略真实动力学/接触 |
| 相对块名义端点误差 | `norm(p_after−p_nominal)`，mm | 当前块累计的理想解释与实际运动之间的偏差；每次新动作块重新锚定 |
| 控制器更新/力矩限幅 | 如25/0：该50ms内25次内部力矩控制，0次至少一个关节输出被限幅 | 不等于VLA调用25次，也不是动作输入裁剪或夹爪开合次数 |
| 关节位置/速度 | 7个臂关节实际qpos/qvel，rad、rad/s | 测量状态；OSC_POSE没有对应的每步7关节目标角，不能拿它冒充关节目标跟踪曲线 |
| 末次力矩命令 | 最后一次内部控制更新的限幅后7维关节力矩，N·m | 送往执行器的命令；不同于同一瞬间测得的实际关节作用力 |
| 命令峰值L2 | 一个控制周期内，7维限幅后力矩向量L2范数的最大值，N·m | 总体命令幅度摘要；不是某个关节的最大力矩，也不是功率或完整高频力矩曲线 |
| 归一化动作/提交命令 | 冻结模型输出与反归一化后控制器输入，均7维 | 前3维平移、后3维旋转、末维夹爪；仍需OSC缩放后才成为m/rad增量，不能直接当关节目标角 |

真实OSC通常基于当前实际位姿构造相对目标；块名义轨迹则从块起点连续累计。二者的参照不同，所以本步跟踪误差只有几毫米，而块累计误差达到几厘米，并不矛盾。名义曲线换块断开，避免把两个重新规划的块拼成一条连续理想轨迹。OGG回合保存的完整块是可能已经受引导的最终块，没有无引导反事实可供恢复。

## 与LVM/OGG一起看

LVM Score描述视觉变化预测与观测的偏离，不是失败概率；Threshold是该回合实际检测阈值。OGG Loss比较候选动作引起的预测变化与待补偿视觉变化，是另一种量。改用MSE后不能把loss数值与余弦loss直接横向排名，也不能把归一化候选动作更新L2当作机械臂移动了多少毫米。

先找重规划事件，再对照：目标是否突然变化；OSC跟踪误差是否升高；力矩是否触及限制；实际位置是否受到物体/桌面接触阻碍。能准确跟随错误目标时，更值得检查策略规划；目标看起来合理但持续跟不上时，再调查控制、动力学和接触。这些只能形成有证据的假设，不能由单个误差值自动归因。原始`contact_count_all_scene`是全场景接触数，也不是抓取成功标签。

本工具没有为跟踪误差设置统一合格阈值；接触阶段、目标大小、控制周期和任务需求均会影响解释。旧实验没记录实际状态时显示“未记录”，不从视频补造。
