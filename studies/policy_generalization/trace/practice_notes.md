## D．已运行：动作块与首次单步动作一致性检查

检查的问题：首次单步动作是否等于动作块的第0行？

- 输入文件：同一次 Trace 的 `action_chunk.pt`、`selected_action.pt`。
- 自己实验目录里的 Tensor 可用 `torch.load(..., map_location="cpu", weights_only=True)` 读取。
- 提示1：先打印两个 shape，找出哪个轴是未来动作位置。
- 提示2：再选择动作块的第0个位置，比较数值；不会时再查 `torch.testing.assert_close`。
- 不需要先实现完整的 `verify_trace()` 或通用测试框架。

笔记本中已经运行的检查（这部分最初由助手提供，不计为独立编写练习）：

```python
chunk = torch.load(trace_dir / "action_chunk.pt", map_location="cpu", weights_only=True)
selected = torch.load(trace_dir / "selected_action.pt", map_location="cpu", weights_only=True)
torch.testing.assert_close(chunk[:, 0], selected)
```

运行结果：云端输出“验证通过：首次单步动作 = 首次动作块的第0行”。
这项检查能说明什么：同一次 Trace 中，首次返回的单步动作与动作块第 0 个位置一致。
它还不能说明什么：动作是否能完成任务，或受到扰动后的成功率是否下降。

## E．已完成：固定初始噪声的亮度对比

本节对应 Notebook 第 4 节；用户已补全三次调用和 `action_mae()`。

| 条件     | 实际设置                                                                  |
| -------- | ------------------------------------------------------------------------- |
| 输入快照 | `trace_day2_003/policy_input.pt`                                        |
| 初始噪声 | 同目录 `initial_noise.pt`，形状 `[1,50,32]`；三次均传入数值相同的副本 |
| 状态     | 同一份标准化后的 `[1,8]` Tensor                                         |
| 语言     | 同一份 `[1,48]` token ID 与 attention mask                              |
| A1 / A2  | 两路原始图像，重复预测两次                                                |
| B        | 两路图像在 `[0,1]` 空间中乘 `0.6`                                     |
| 调用方法 | `policy.predict_action_chunk(batch, noise=...)`，直接生成动作块         |
| 输出     | 三组 `[1,50,7]`，仍在归一化动作空间                                     |

自己实现的指标：

```python
def action_mae(a, b):
    assert a.shape == b.shape
    difference = a - b
    absolute_difference = difference.abs()
    mean_absolute_difference = absolute_difference.mean()
    return mean_absolute_difference.item()
```

| 比较     | 云端已保存的实际输出          |
| -------- | ----------------------------- |
| A1 与 A2 | MAE = `0.0`                 |
| A1 与 B  | MAE = `0.10071975737810135` |

解释：在这个观测与初始噪声样本上，重复预测一致，而亮度扰动改变了预测动作。
MAE 是 350 个动作分量的平均绝对差，不是百分比、物理单位误差或任务失败率。
还不能概括其他观测、随机噪声、亮度强度与相机视角下的行为。

本地整理时保留用户的循环和指标实现，亮度运算改成从 `batch_cpu` 原图计算，
避免单独重复运行时把亮度从 `0.6` 倍继续变成 `0.36` 倍。
这是整理后的改进，尚未在本地 GPU 上重跑；上表是整理前云端已执行的结果。
