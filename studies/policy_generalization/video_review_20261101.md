## 关于 view_10 /1000 /20 的遮挡

物体在画面里看不见，不等于物体回到地面。原始记录显示：

| 仿真时刻 | 物体抬升 | 双侧接触记录 | 物体在夹爪坐标系中的位置（cm） |
| ---: | ---: | --- | --- |
| 5.00s | 14.77cm | 有 | [1.17, -1.54, 0.66] |
| 5.50s | 14.16cm | 有 | [0.22, -3.57, 0.35] |
| 6.00s | 14.10cm | 无 | [-3.61, -6.54, -6.45] |

这支持“物体与夹爪的相对关系发生改变、随后失去双侧接触”。
物体可能仍被篮沿或其他结构支撑，但本采集器没有记录目标-篮子接触，不能据此确认支撑对象或碰撞因果。
相关时刻是控制区间采样边界，不是连续碰撞的精确起止时间。

## 降低人工复核成本的办法

已实现 [review_grasp_events.py](review_grasp_events.py)：读取已有 Tensor/JSON，不启动模型、仿真或 GPU。

1. 数据筛选首次双侧接触、10cm抬升、抬升后5cm高度下降、连续三窗缺少双侧接触、夹爪坐标系中3cm相对位移的线索。
2. 按实际控制频率把事件映射到视频帧，附加全回合稀疏帧，生成带时刻的拼图；六秒以后的帧标为 video only。
3. 助手先看数据和拼图，写候选失效阶段及不确定项；人工只核对遮挡、碰撞和事件边界。

这些阈值只是离线筛片段的约定，没有在保留结果上重选策略，也不是已验证的稳定抓取分类器。
正常放置同样可能产生高度下降和接触消失；因此工具输出中性事件与最终结果，不直接把阈值触发等同于失败。
稀疏帧会遗漏短事件，有疑问时再看事件附近连续视频，避免要求人工重新描述整段。

例子（从仓库根目录、已有 CPU PyTorch 环境执行）：

```bash
python -m studies.policy_generalization.review_grasp_events \
  --run-dir outputs/smolvla_heldout_camera_20261031_001/n_action_steps_20/view_10/seed_1000 \
  --output-dir outputs/smolvla_heldout_camera_20261031_001/analysis/event_review_20261101 \
  --frames
```

导图另需 ffmpeg/ffprobe 和 Pillow。本轮已实际处理六个案例并生成 JSON 与拼图，四项 CPU 边界测试通过。
原始视频和拼图留在本地 outputs；公开仓库发布代码、脱敏数值和本文的复核结论。

## 当前研究问题如何收窄

当前可区分三类现象：初始有效夹持失败、抬升后的掉落/搬运失效、状态改变后未能有效恢复。
view_5 /1001 /20 是恢复成功的具体反例，不能说所有意外位移都无法处理；其余空抓循环说明恢复能力仍有明显边界。
物体碰倒和掉落是运行中的结果，并非预先独立控制的位移变量，本批不能报告“已系统评测目标位置突变鲁棒性”。
下一步先完成现有案例的分段和可复查报告，再决定是否需要设计独立的恢复实验；当前不消耗远程 GPU。
