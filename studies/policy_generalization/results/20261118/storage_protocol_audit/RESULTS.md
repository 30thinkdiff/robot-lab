# 多层特征容量与Object10正式协议复核 · 2026-11-18

本次只读核查远程NPY文件头、目录占用、容器内存、冻结部署源码、训练协议及正式Trace；未加载大特征张量、未训练、未启动GPU或仿真，未删除或改写旧数据。原始私有快照保存在本地忽略目录，公开[核查收据](receipt.json)只保留必要数值与SHA。

## 1. 70条与454条的存储需求

70条正式J数据共10,265帧，50条训练、20条验证。原MLP数据共454条、66,984帧，364条训练、90条验证。这里的70不是70条全部用于训练；容量按训练与验证合计计算。

| 特征缓存                     |      70条实际文件体积 | 原454条规模的张量载荷估算 |
| ---------------------------- | --------------------: | ------------------------: |
| Block 2 FP16                 |           约30.073GiB |                196.242GiB |
| Block 8 FP16                 |           约30.073GiB |                196.242GiB |
| 两层合计                     |          60.146501GiB |             392.484375GiB |
| Connector INT8＋FP16量化尺度 |           1.177200GiB |               7.681681GiB |
| 三层合计                     | **约61.324GiB** |    **约400.166GiB** |

逐一检查140个原始层NPY文件头，形状均为`[N,2,1024,768]`、FP16。每帧每层3MiB，两层6MiB，因此不能只按Episode数量粗略等比例估算。Connector是既有`[N,128,960]` INT8特征及`[N,128]` FP16尺度，并未另存与原始层一样大的张量。70条两层文件的实际分配空间为60.147186GiB；NPY头与文件系统分配误差很小。

其中新提取65条、9,516帧约55.758GiB在数据盘`corrector/j36m/raw70`；复用的5条、749帧约4.389GiB在系统盘两个`multilayer_export_*`目录。**不能只看raw70目录就以为70条只占55.76GiB。** 原始层缓存中没有再复制一份未来变化量，训练时按需计算`Z[t+10]-Z[t]`。

扩到454条会比现有70条再增加约332.338GiB的两层FP16特征。若保持目前环境、全部结果和已有数据，数据盘使用量由118.923GiB增到约451.261GiB；500GiB数据盘可留下约49GiB空间供新增Checkpoint、临时文件和少量实验。130GiB盘无法容纳；500GiB是基于当前文件保留方式的估算，不代表任意新实验都足够。两层约392.48GiB是张量本身的下限，400.17GiB尚未包含环境、原始Parquet、图像样本、实验视频和新训练状态。压缩或降低分辨率会改变当前缓存/数值协议，本次未实施。

“制作数据占多少内存”需要分开理解：上述数字是**磁盘存储**，不是CPU RAM峰值。提取器逐Episode写NPY，训练用memmap按需读取，不要求把60GiB缓存整体装进RAM。不过提取时会解码Parquet图像、保留短历史、运行编码器及生成临时张量，仍有RAM/显存开销。旧提取报告与监督日志没有记录进程RSS/VmHWM，**无法事后给出可信的历史CPU RAM峰值**；过去120GiB实例配额也不等于实际峰值。下次少量真实提取应增加独立RSS/显存采样再定RAM预算。

## 3. 必须区分早期V3与最终六方法部署

| 实验版本                                                   | 阈值历史                                    |      cooldown | 中断时尚未到期的单动作预测 |
| ---------------------------------------------------------- | ------------------------------------------- | ------------: | -------------------------- |
| 早期V2 `object_..._002`                                  | 独立正常轨迹历史冻结                        |          20步 | 取消                       |
| 预测保留V3 Pilot `object_..._003`                        | 仍冻结，保持单变量对照                      |          20步 | 保留                       |
| **Object10六方法正式配对** `expanded_.../ordinary` | **上游动态历史，每回合重新bootstrap** | **0步** | **保留**             |

因此，“目前不是V2而是V3，所以所有设置都恢复了”这个说法不够准确：V3 Pilot只修预测保留；正式六方法是**后续expanded独立部署**，再恢复动态阈值及0冷却。早期结果继续按其原协议保留，不改写为正式结果。

实际冻结源码调用链为`DynamicJoint → RetainedJointCorrector → JointOnlineCorrector → OnlineCorrector`。冻结父类仍包含正常历史冻结、cooldown20及取消预测的代码，但正式子类在初始化后替换了状态、threshold_step和interrupt，不能只读父类就判断正式行为。

正式源码`expanded-4fe058f5c20c`与plan中的入口SHA、适配器SHA、核心manifest SHA全部一致；[收据](receipt.json)保存完整SHA及两个模型Checkpoint SHA。历史MLP四组240回合复用，J两组新测120回合；共同条件为Object10 task0—9、init0—2、eval seed1000/1001。四次桥接的完整性检查沿用原正式报告。

### Trace独立重算

在CPU上直接执行冻结上游的`RobustThresholdState/robust_threshold_step`，每回合建立默认空状态，逐步重放保存的评分：

| 方法    | 回合 | 评分步/预热后可评分步 | 阈值不一致 | 触发不一致 | 额外最长空窗 |
| ------- | ---: | --------------------: | ---------: | ---------: | -----------: |
| J-LVM   |   60 |             7611/7611 |          0 |          0 |            0 |
| J-OGG   |   60 |             7615/7615 |          0 |          0 |            0 |
| MLP-LVM |   60 |             7585/7585 |          0 |          0 |            0 |
| MLP-OGG |   60 |             7578/7578 |          0 |          0 |            0 |

合计**240回合、30,389次评分**，阈值最大绝对误差0、触发差异0。J日志中融合score保留Python float，但控制接口会先转换成FP32 Tensor；复核遵循这一步真实转换，不能用日志高精度值直接代替控制输入。所有方法首评分在step24；20步预测跨度加4步起始预热，不算监测空窗。

两组J取消计数均0，并记录了842/877次跨重规划后仍到期评分的预测。这不仅是“没有取消计数”，还存在明确的保留后评分证据。MLP旧Trace没有新增cross-replan诊断字段，其该字段缺失不等于从未跨重规划；其逐步评分同样完整。

### “其他完全一样”仍不成立

共同的是上游LVM状态机/默认参数、动作队列中断机制、20Hz控制、1秒预测跨度（训练10Hz的10帧对应在线20步）、50步动作块、10次去噪、OGG eta=1及每3次去噪引导一次、相同冻结FP32 VLA和任务条件。动态阈值**规则**相同，数值随各自分数历史变化，不能要求每时刻阈值数值相同。

除架构/视觉输入输出与损失以外，还存在这些实际差异：

1. **训练数据与训练配置**：J为50训练/20验证；旧MLP为364训练/90验证。J为FP32、有效batch32、60轮且本组patience0；MLP为AMP BF16、有效batch512、最多150轮及patience5。这是部署系统对比，不能作为严格只改架构的消融。
2. **视觉编码计算精度**：VLA两边均FP32，但J另用冻结BF16视觉编码器匹配其原始层提取协议，MLP使用FP32策略编码器。
3. **J评分/引导的融合与有效性筛选**：独立正常轨迹校准仍用于三层权重`0.417925/0.288372/0.293703`（Block2/Block8/Connector）及每层RMS门限`0.009642/0.022144/0.186612`；无效层排除并重新归一化。**正式实验没有冻结阈值历史，但不能说完全没有正常轨迹校准。** 这组评分权重也不是训练损失的0.25/0.25/0.5。
4. **OGG误差组成**：本轮MLP为单层余弦损失，J为有效三层加权余弦损失，均没有在线MSE项。训练中的归一化MSE＋余弦不能混称为在线OGG损失。两者都由当前视觉＋候选首动作预测1秒后的视觉变化，并非A10未来动作序列条件。

复核结论：用户列出的三项早期行为中，**冻结阈值历史、20步冷却、取消待到期单动作预测均不属于最终六方法实际设置**；但训练数据规模、训练配置、视觉编码精度和分层校准仍需列作比较限制。
