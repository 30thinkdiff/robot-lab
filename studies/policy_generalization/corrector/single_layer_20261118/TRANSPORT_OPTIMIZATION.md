## 改了什么

1. 文件原本就是FP16，CPU只读取并拷贝原始FP16当前帧和未来监督帧，仍逐样本检查非有限数值。
2. 
3. **先将两帧恢复成FP32，再以FP32计算future−current。** 没有以FP16相减，没有新量化或改变模型/优化器精度。
4. 仅将`z_t/a_t/delta_z`交给原训练接口；未来帧始终只用于监督目标，不传入模型条件。当前单动作、两个相机、所有Token、原样本顺序、时间跨度和索引不变。
5. 最终选4个加载进程；不使用DDP，不改有效batch512、原MSE＋cosine、AdamW、调度、梯度裁剪、150轮/patience5与验证total-loss选best。六组排程未缩减。

代码位于`packed_pipeline.py`；原`data.py`和`training.py`仍保持SHA不变，冻结模型/训练函数继续直接复用。入口只在本训练进程范围内替换loader与move，不编辑第三方包。生产代码、验收、配置及来源断点均有独立SHA绑定。

## 增加4090的可选方案（未租用、未启动）

| 方案                              | 用途与约束                                                                                                                             |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 同一实例两张GPU，共同训练一个模型 | 需要独立DDP实现、全局batch512/尾组/梯度累积/随机数与恢复验收；增加卡不会让当前单卡代码自动提速，不能承诺两倍                           |
| 同一实例两张GPU，各跑一组         | 不同步梯度，较容易保持每组原训练协议；同层不同seed可共享文件页缓存。CPU/RAM随卡数增加，但SSD吞吐仍需测                                 |
| 北京B区其他机器的单卡，各跑独立组 | 可行；建议当前机器负责S2三seed、新机负责S8三seed。只需一次迁移相应层数据/元信息/环境并完整验收，无逐步网络同步；加速的是六组总完成时间 |
| 跨机器共同训练同一个模型          | AutoDL目前不支持为此开放4090跨机内网，公网通信成本与复杂度高，本项目不优先采用                                                         |

若296没有空闲GPU，当前实例不能直接增加另一主机的GPU。可等296释放，或按平台迁移/克隆到有足够卡的北京B区主机，再选同一实例的GPU数量。若另开单卡实例，已有S8主要特征载荷约196GiB，另需环境、元信息、checkpoint及安全余量；不必重新提取。仅复制所需层的部署必须另做对应SHA/数据与队列分片验收，不能拿源机完整验收冒充新机已验收。
